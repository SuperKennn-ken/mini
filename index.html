🔎 Case study

Brief → Tense Train

“A 3-minute game for Grade 3 to practise choosing past, present or future verb forms using time words.”

🧠 Design decision

The time word (yesterday, every day, tomorrow) carries the meaning, so it sits right next to the gap. Learners then train the habit that matters: look for the time clue first.

🎮 Mechanic

Drag the verb form into the sign. Younger players can also just tap it. The train leaves only after the right answer, which makes a satisfying payoff that kids want to see again.

🔁 Iteration

The first version only said “Wrong!”, so kids guessed at random. In the next version, a mistake shows the rule (“Tomorrow → future”). That one change ended the guessing, so it became a design principle.

📦 Hand-off

The sentences live in a TENSE data array. A teacher can add “Last summer we ___ to Spain.” without touching the game code.

script.js · BaseScene shared by every mini game
// Every game extends one base scene, so scoring,
// streaks and feedback feel consistent across the suite.
class BaseScene extends Phaser.Scene {
  addPoints(points, x, y) {
    this.streak++;
    const bonus = this.streak >= 3 ? 5 : 0;
    this.score += points + bonus;
    this.popText(x, y, `+${points + bonus}`, '#16a34a');
    this.burst(x, y);            // confetti particles
    SFX.play('correct');        // synthesized, no files
  }

  miss(x, y, hint) {
    this.streak = 0;
    this.cameras.main.shake(150, 0.006);
    // Mistakes teach: show WHY, never just "wrong"
    this.popText(x, y, hint, '#dc2626');
  }

  track(item, correct) {
    // Missed words come back sooner (spaced repetition)
    correct ? markHit(item) : markMissed(item);
    // xAPI-style event any LMS can listen to
    emit({ verb: 'answered', item, correct });
  }
}

// Content is pure data: teachers can swap word lists
const TENSE = [
  { pre: 'Yesterday I', ans: 'went', post: 'to the park.',
    hint: 'Yesterday → past tense' },
];

🌱 Design principles

Built for language learners

Six rules I follow so the games stay both fun and effective.

⚡

Instant feedback

Every action gets a reaction within a few hundred milliseconds, with sound, motion and colour together.

🤗

Safe to fail

Mistakes show the right answer and explain why. Streaks reward success, but nothing shames the learner.

🔁

Many short reps

Three-minute sessions full of repetition work better than long levels, both for memory and for the class timetable.

🖼️

Comprehensible input

Pictures, audio models and context make the meaning clear before we ask learners to produce language.

🪜

Scaffold, don't solve

Hints reveal one step at a time and keep correct work locked in, so learners finish the task themselves.

👩‍🏫

Teacher friendly

Content lives in simple data files, the games run in any browser, and results are easy to report.

❓ FAQ

Good questions

How fast can you deliver a playable prototype?

For a focused mini game like the ones on this page, a grey-box playable usually takes 2–3 days from an approved brief. After that come a playtest round and polish. Simple variations on an existing template can be quicker.

Can teachers or content writers change the words and sentences?

Yes. All content is kept separate from the game logic in simple data arrays or JSON. Try the Content Lab above: updating a word list, sentence set or riddle pack doesn't require touching the Phaser code.

How is the code organised?

Markup, styles and logic are kept separate: index.html, style.css and script.js. Inside the script, every game extends one BaseScene, and content data sits in its own block. For production, I'd split each scene into its own ES module and bundle it with Vite.

Will the games work on tablets and Chromebooks?

Yes. They use Phaser's Scale Manager to fit any screen, support touch, mouse and keyboard, and stay lightweight, so they load well on school networks and older devices.

What about accessibility?

Every game has large tap targets, audio for its instructions, a mute button, colour combined with text and icons (never colour alone), reduced-motion support on the page, and no time pressure in the listening and reading games.

Do you work with custom art and voice-over?

Absolutely. The demos use emoji and synthesised sound so they need no extra files, but production builds can use your illustrator's sprite sheets, animations and professional voice recordings through Phaser's loader.

Can the games be embedded in our app or LMS?

Yes. Each game can be built as a standalone bundle and dropped into an iframe, a React/Vue app, or a SCORM/xAPI package, with events for score and completion. The demos already send these events.
